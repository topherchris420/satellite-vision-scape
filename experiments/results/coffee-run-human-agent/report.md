# The coffee run: a person, the scripted baseline and the chance floor

<sub>Experiment `coffee-run-human-agent` · generated by `bun run experiment report coffee-run-human-agent` from the trace files below · **PARTIAL**</sub>

## Question

How does a person's coffee run compare with an agent's on what the world can measure for both: time, route, collisions and coffee retained?

## Hypothesis

On the coffee run, the scripted baseline (smooth executor driving) retains more coffee than a person, while a person is faster; the random agent almost never delivers. This is a comparison of observable behaviour, not a contest: perception and motor control differ between the columns.

**We would reconsider it if:**

- the random agent delivers as often as the baseline: the coffee run would not discriminate at all

**It is supported if:**

- the random agent delivers far less often than the baseline (the floor is low)

## Why we asked

The README says no human reference run is committed and that a side-by-side comparison is something you record yourself. Human sessions now record route samples, overshoots and the same windows as agents, so a person's exported trace can be imported into this experiment and compared on shared metrics only.

- README.md: 'No human reference run is committed yet'
- tests/agent-motor.test.ts: smooth vs aggressive driving, 100% vs 11% coffee

## Design

- **Independent variable:** `provider`: Who decides: the scripted baseline, the seeded random agent, Jev, or a person.
- **Held fixed:** nothing beyond the world and task
- **Episode:** from the start of After Hours until the coffee reaches the technician (at most 300 simulated s)
- **Runs:** 10 per condition; run *i* of every condition uses seed 1 + *i* (paired)

| Condition | Setting | Provider | Runs | Repeats exactly? |

## Limitations

- Human runs are recorded in the browser and imported; their seeds are not controlled, so human comparisons are measurements only, never verdicts.
- A person perceives pixels and audio and steers every frame; agents read text and use the shared executor. Only world-measured metrics are compared.
- The random agent may choose 'hand control back', which ends its run: that is what the random provider does in the product too.
- The scripted baseline is a hand-written policy, not a model: its results describe what the world does to that policy, not what any model would do.
- Metrics are computed in the client from the session's own records; nothing here is server-attested.
